# ADR-0003: التكامل مع Model Context Protocol (MCP) في Nabd

* **الحالة:** مقترح (Proposed) — بانتظار مراجعة معمارية وأمنية
* **يعالج:** توسيع منظومة الأدوات — لا issue مفتوح بعد
* **مرتبط:** `docs/THREAT_MODEL.md` (التحديث في Phase 0)، `docs/DECISIONS/0002-user-facing-language.md` (نمط حقل Reason)

## السياق

يعتمد Nabd واجهة أدوات موحدة `Tool { Name / Spec / Run }` (`internal/tools/registry.go`). الأدوات الحالية محلية صرفًا: قراءة الملفات، البحث، الكتابة، التعديل، bash، وأداة المهارات الاختيارية. كل أداة تخضع لنظام الأذونات (`internal/perm`) وسياسات الوصول للملفات وتنقية المدخلات والمخرجات.

السجل الحالي لا يحتوي أي آلية لاكتشاف أدوات خارجية أو استدعائها:
- لا عميل MCP في الاعتماديات (`go.mod` خالٍ تمامًا — فُحص عند `cb9167e`).
- إعدادات v2 (`~/.ag/config.v2.json`) ترفض الحقول غير المعروفة.
- بدء الجلسة (`cmd/ag/session.go`) يربط الأدوات المحلية والأذونات والمهارات فقط.

بروتوكول MCP هو المعيار المفتوح لربط النماذج بمصادر خارجية. إضافته تغيّر حدود الثقة التي بُني عليها النموذج الحالي، لذلك يُعامل تكاملًا خارجيًا يحتاج طبقة أمان مستقلة، لا مجرد أدوات إضافية.

وجود مخاطر في `bash` (صلاحيات مستخدم Termux بعد الموافقة) **لا يخفّض** متطلبات التكامل الخارجي.

## القرار

اعتماد **الخيار A المشروط**: MCP Adapter مستقل عن النواة، وفق الضوابط التالية:

### القرار المبدئي
- **STDIO فقط** في v1؛ رفض صريح لـ Resources وPrompts وSampling.
- MCP **معطّل افتراضيًا**؛ لا تُشغَّل الخوادم عند بدء الجلسة (Lazy Startup).
- موافقة المستخدم الأولى إلزامية لكل خادم.
- التصنيف الأمني (ReadOnly / Write / Execute) من الإعداد المحلي حصرًا — **ادعاء من المستخدم، لا تحقق من Nabd**.
- لا تجاوز لسلم Permission أو Safefs أو سياسة التنقية القائمة.
- أي نقل شبكي يتطلب ADR مستقلًا.
- تحديث `docs/THREAT_MODEL.md` قبل أي كود إنتاجي.

### جملة حاكمة للقراءة
> موافقة الخادم + تصنيف محلي `ReadOnly` → تنفيذ ضمن سلم الأذونات دون سؤال إضافي. **المخرجات تبقى محتوى غير موثوق** ولا تُعامل كقراءة محلية موثوقة أو كضمان Safefs.

### البنية

```text
Model -> Tool Registry -> MCP Tool Adapter
  -> Schema + Size Validation
  -> Local Permission --(Deny)--> Reject
                     --(Allow)--> MCP Client -> External Server
  -> Output Limits -> Untrusted Content -> Model
```

- لا تتسرب اعتماديات MCP أو تفاصيل البروتوكول إلى `internal/tools` أو `internal/perm` أو `internal/safefs` أو أي نواة أخرى.
- قرارات الصلاحيات تبقى داخل Nabd، ولا تُفوَّض لخادم أو لمحتوى استجابة.
- **نص صريح:** صندوق «Local Permission» هو نفس `perm.Policy` ونفس `Registry.Class` ونفس `wirePathRule` (`cmd/ag/session.go:114`) — الكود يرفض أن يحكم قراران مختلفان على الأداة والمسار (`registry.go:38-40`).

### حدود عملية STDIO

**STDIO ليس آلية عزل أمني.** خادم STDIO عملية محلية تعمل بصلاحيات مستخدم Nabd، وقد تصل إلى ما يصل إليه المستخدم، وقد تفتح اتصالات شبكية مستقلة عن قناة MCP.

**واقع Termux:** لا يُفترض توفر احتواء على مستوى النظام (صندوق Landlock غير متاح لعملية تطبيق Termux).

**B7 المبدئي (مُحسم):** المسار 2 — قبول مخاطر تشغيل العملية بصلاحيات المستخدم، مع تحذير صريح في الموافقة الأولى، وصف NOT PROVIDED في نموذج التهديد.

### التسمية (§7) — قرار: نمط skill لا أسماء ديناميكية

**ملاحظة:** سُحب اقتراح قاعدة الشكل `^mcp__...$` عبر `fenceToolName` — يتناقض مع نية `fence.go:93-95` (منع رؤية النموذج لاستدعاء يُجاب بنتيجة أداة أخرى).

**المشكلة:** مسار العرض يقفل المفردات وقت البناء (`internal/toolvocab/vocab.go:7` — 7 أسماء ثابتة). أي اسم خارجها يُعرض «unknown» على السلك (`messages.go:259-270,288`)، واختبار `registry_parity_test.go` يفرض التساوي. أسماء MCP ديناميكية = انهيار التمييز.

**القرار:** إعادة استخدام نمط skill المُثبت:
- اسم ثابت واحد في المفردات: `mcp_tool` (يُضاف لـ vocab).
- هوية الخادم/الأداة (`server-id` + `tool-name`) داخل الوسيط، لا في الاسم.
- الناتج عبر `GuardedOutcome` (`tools/skill.go:65`) — يمنع خلط النتائج (fence.go:93-95).
- `server-id`: `[a-z0-9-_]{1,32}`؛ `tool-name`: `[a-z0-9_-]{1,64}`.
- أي تعارض مع أسماء محلية يُرفض.

### الإعدادات (§5.1)

- تُحمَّل إعدادات MCP من نطاق المستخدم فقط: `~/.ag/mcp.json`.
- **التقليد القائم مُتحقَّق منه في `internal/config/v2.go:60-72`**: المشتركات في `~/.ag/` هي `config`، `config.v2.json`، `auth.json`، `providers.json`، `sessions/` (مخزن `shadow/` في `<root>/.ag/shadow` — داخل المشروع). وجود موقع ثانٍ يخلق خطر تعارض ويجعل تدقيق الأسرار أصعب.
- **استثناء موثّق:** مهارات المستخدم في `~/.config/nabd/skills` (`internal/skill/skill.go:129-131`) — خارج نطاق هذا القرار.
- يُرفض تحميل أي إعداد MCP يقع **داخل جذر المشروع**، بغض النظر عن اسم الملف أو المجلد (المعيار هو الموقع لا الاسم). يشمل الرفض `mcp.json` و`.mcp.json` و`.ag/mcp.json` داخل المستودع.
- الأسرار كمراجع لأسماء متغيرات بيئة فقط (`${VAR}`)، لا قيم صريحة.
- الدليل `0700`، الملفات `0600`، بلا بتات group/other، فحص المالك، حد 256 KiB.

### الموافقة والبصمة (§6)

**الموافقة الأولى** تعرض: `server-id`، المسار التنفيذي المطلق وargv، الوسائط الثابتة، نطاق متغيرات البيئة، الصلاحيات المقررة محليًا، قيود الاحتواء أو التحذير الصريح (B7 مسار 2)، وبيان أن الخادم غير موثوق افتراضيًا.

**بصمة الأداة:** SHA-256 على تقنين JSON قانوني (التقنين على الشجرة الخام via `json.Number` — إعادة الترميز عبر `float64` تفسد الأعداد الكبيرة — بمتجهات اختبار RFC 8785؛ إن لم تُثبَّت JCS بدقة سُمّيت «canonical JSON») لحقول: `server-id`، اسم الأداة، وصفها، `inputSchema`، وجميع الحقول الأخرى (بما فيها التلميحات). أي تغيير يُبطل الموافقة.

**تكامل واجهة الموافقة (§6.4):** تُعرض الموافقة الأولى وموافقة Write/Execute عبر نافذة الأذونات الحالية في Feed UI (`internal/ui/modal.go`)، لا عبر مسار موازٍ. النافذة الحالية تعرض الاسم + الوسائط + السبب فقط، لذلك يُقيَّد مسبقًا حقل سجل بنيوي إضافي (الاسم المقترح `PermDetail`) بأقصى حدود وقائمة مغلقة — على نمط حقل `Reason` في ADR-0002 — يُبنى من بيانات محلية (البصمة + الإعداد)، ولا يظهر فيه نص حر من الخادم. التفاصيل التنفيذية في Phase 3.

### تفاعلات سلم الأذونات

- **YOLO:** أدوات MCP المصنفة Mutating/Executing **خارج YOLO قطعًا** — لا تُنفَّذ صامتة حتى تحت YOLO، ولا يُغيَّر هذا إلا بـ ADR جديد. السبب: التصنيف ادعاء مستخدم لا تحقق منه Nabd، ومنح تنفيذ صامت لأداة خارجية بتوجيه نموذج خطر غير مقبول.
  - **تنفيذ بنيوي:** الاستثناء في `perm.Policy` نفسه (على نمط استثناء `bash`)، لا ضمني بالفئة. الاختباران `TestYOLODoesNotApproveMCPWrite` و`TestMCPNoSessionGrant` يُكتبان قبل أي تنفيذ.
  - **تعيين المصطلحات:** Write→`Mutating`، Execute→`Executing` (أسماء `perm.Class` الحقيقية).
- **منح الجلسة (P3ب — قرار معتمد: الخيار أ):** لا يُمنح أي استدعاء MCP صلاحية جلسة عبر `AllowSession` في v1 — لا Write ولا Execute.
- **الموافقة المحفوظة:** يجوز استخدام موافقة تفاعلية سابقة لتشغيل أداة مصنفة محليًا كقراءة، بشرط: تطابق هوية الخادم (`server-id`)، وتطابق بصمة الأداة، وعدم تغيّر السياسة المحلية.
- **Write/Execute:** تتطلب موافقة منفصلة لكل تنفيذ — حتى تحت YOLO. تُرفض في `headless` لاستحالة تحصيل الموافقة التفاعلية.
- **Headless للقراءة:** لا تُنفَّذ أداة قراءة دون سجل موافقة صالح من جلسة تفاعلية سابقة. عند غياب السجل أو تغيّر البصمة: رفض + طلب إعادة المراجعة تفاعليًا.
- **الخطر المتبقي:** موافقة الخادم قد تفتح أدواته القرائية ضمن نطاق الموافقة والسياسة. يُوثَّق النطاق وإلغاء الموافقة واكتشاف الأدوات الجديدة في `THREAT_MODEL.md`.
- **أوضاع الرفض** (`ModePlan`/`ModeDeny`/`ModeAllowReads`) تعمل تلقائيًا عبر نفس `Policy.Check`.
- **Headless:** `silentAsker` يرد `Deny` — الموافقة الأولى **لا يمكن تحصيلها headless أبدًا**. أدوات ReadOnly المعتمدة مسبقًا تعمل؛ الباقي يُرفض.

### سلوك headless (§4.3)

لا يمكن منح موافقة أولى بلا TTY. في الوضع headless: أدوات MCP المصنَّفة ReadOnly فقط تعمل بوجود سجل موافقة سابق (سلوك السلم الحالي)، وأدوات Write/Execute تُرفض عبر `silentAsker`.

### مفتاح التعطيل (§14)

علم `--no-mcp` **بند Phase 5**، لا Phase 0 — لا يُضاف علم ميت قبل وجود المحرك.

## البدائل المرفوضة

* **الخيار B — التأجيل الصريح:** مرفوض كقرار نهائي، مقبول كمرحلة. المخاطر في `bash` لا تبرر ترك التكامل الخارجي بلا حوكمة إن طُلب مستقبلًا.
* **الخيار C — عبر skills (وسيط):** مرفوض. التفاف غير مرئي على الحوكمة الأمنية أسوأ من التكامل الصريح.
* **دعم شبكي (SSE/Streamable HTTP) من البداية:** مرفوض. يُعاد النظر بعد استقرار STDIO عبر ADR مستقل.
* **مسار XDG (`~/.config/nabd/`):** مرفوض. التقليد القائم `~/.ag/` مُتحقَّق منه في الكود.

## القرارات التفصيلية

### حدود الثقة

**غير موثوق افتراضيًا:** الخادم نفسه، أوصاف أدواته، `inputSchema`، البيانات الوصفية (بما فيها `readOnlyHint`)، وسائط الاستدعاء من النموذج، مخرجات الأدوات وأي تعليمات مضمّنة فيها.

**فصل الضمانات:** Display Sanitization (حماية العرض) ≠ Input Validation (صحة البنية) ≠ Authorization (الإذن بالتنفيذ). نجاح التنقية أو التحقق ليس دليل موثوقية.

**وسم المحتوى غير الموثوق:** تُعاد استخدام الآلية القائمة — fence بـ nonce (`agent/fence.go:19-49`) و`GuardedOutcome` — لا مسار ثانٍ.

### الأذونات

- التصنيف من الإعداد المحلي حصرًا؛ تلميحات الخادم لا تُستخدم كمصدر ثقة.
- أداة غير مصنَّفة تُرفض.
- ReadOnly: تُسمح بعد موافقة الخادم ضمن السلم، لكن **مخرجاتها تبقى غير موثوقة**.
- Write/Execute: موافقة إضافية وفق السلم المحلي.
- موافقة الخادم ≠ موافقة على كل عملياته؛ أي تغيير في البصمة يستلزم إعادة موافقة.
- مخرجات الأدوات لا تطلب ولا تمنح ولا تغيّر صلاحيات (منع تجاوز الصلاحيات).

### الموثوقية

- إعادة المحاولة مسموحة للاتصال/المصافحة فقط؛ **ممنوعة** لـ `tools/call` (خطر تكرار الأثر).
- المهلات: إلغاء عبر البروتوكول، ثم إنهاء العملية الفرعية والتابعة؛ لا عمليات يتيمة.
- **التزامن:** حد أقصى للاستدعاءات المتوازية لكل خادم (يُحدَّد في التنفيذ)؛ الزائد ينتظر ضمن المهلة ثم يُرفض؛ لا تكديس بلا حد.
- سقوف موثّقة لأحجام: `inputSchema`، عدد الأدوات، الأوصاف، الوسائط، المخرجات.

### السجل والخصوصية

يُسجَّل: معرّف الخادم، اسم الأداة الكامل، قرار الأذونات، الأوقات والمدد، الأحجام، Hash الوسائط، الحالة. **لا** وسائط أو مخرجات خام افتراضيًا.

### الاعتماديات

- **القرار (S4، 2026-10-10، ammar): التنفيذ الداخلي المحدود (stdlib-only).**
  - الأرقام: SDK v1.8.0 = 235 حزمة / 13 وحدة خارجية / حواف انتقالية؛ stdlib = 76 / 0.
  - `net/http`+`crypto/tls` من stdlib — لا حجة من GOMODCACHE (96M رقم خام لا صافٍ).
  - النطاق ضيق (initialize/tools.list/tools.call على stdio)، والبروتوكول مثبَّت عند 2026-07-28.
  - التزام Phase 1: مجموعة اختبارات للعميل الداخلي + حارس `TestMCPDependencyIsolation` يبقى كما هو.
- **المثبت لـ S4 (مرجعي):** `github.com/modelcontextprotocol/go-sdk` @ `v1.8.0` (commit `3f3b699b2b67e1ed033a63d6651671dab53c2d32`).
- **نسخة البروتوكول المعتمدة:** 2026-07-28 — التفاوض مقيّد بها صراحةً؛ لا تفاوض على نسخة أحدث دون قرار.
- حصر الاعتماديات في طبقة التكامل؛ حراسة `go list -deps` لكل حزمة نواة على حدة (تشمل الانتقالية).
**قائمة الحزم الصريحة:** `tools`، `perm`، `safefs`، `redact`، `snap`، `store`، `toolvocab`، `ignorefile`، `agent` — لا `provider` بطبيعة الحال.
- Primitives قابلة لإعادة الاستخدام من `bash.go`: `sanitizePath`، `childEnvAllowlist`، `Setpgid` + `killGroup` (مع قاعدة «لا كنس لمجموعة بعد Wait»). تُدرج كأساس Phase 2 مع قاعدة «تكرار مقصود + اختبار تطابق» لتفادي اعتماد نواة→mcp.
